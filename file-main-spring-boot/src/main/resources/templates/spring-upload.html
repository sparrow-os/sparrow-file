📌 大文件上传返回 413 的结论备忘（/upload.json 链路）

记录时间：2026-09-09 · 范围：仅 Spring MVC 的 /upload.json（FileController.uploadFile，MultipartFile）；老 /file-upload servlet 不在本备忘范围。

① 先理解 Spring Boot 的默认 multipart 上限（MultipartProperties）

Spring Boot 对「通过 MultipartFile 接收的上传」有两道默认上限，均未在 application.properties 里配置时按默认值生效（源码见 Boot 的 MultipartProperties.java）：

配置项默认值含义
spring.servlet.multipart.max-file-size 1MB（DataSize.ofMegabytes(1)） 单个文件的体积上限。超过它就在 1MB 处被拦，文件进不了业务代码。
spring.servlet.multipart.max-request-size 10MB（DataSize.ofMegabytes(10)） 整个 multipart 请求体上限（含文件 + 表单字段 + multipart 边界开销），需 ≥ max-file-size。 
// spring-boot-autoconfigure → MultipartProperties.java（默认值）
private DataSize maxFileSize = DataSize.ofMegabytes(1);      // 单文件 1MB
private DataSize maxRequestSize = DataSize.ofMegabytes(10);  // 整个请求 10MB
⚠️ 曾踩过的坑：项目原没配这两个 key，一律按默认值 1MB 拦截 —— 想收 5MB 文件必须先调大。 现已覆盖为：max-file-size=8MB / max-request-size=16MB。 注意：这只是"容器接收上限"，不等于各业务 pathKey 允许的大小（后者在业务层按 fileConfig.getLength() 精确限制，见 ③④）。
# application.properties 放开接收上限（示例）
spring.servlet.multipart.max-file-size=8MB
spring.servlet.multipart.max-request-size=16MB

② 为什么「没配任何 advice」直连也返回 413 根因

超过上限时，Spring 在 multipart 解析阶段抛出的是 MaxUploadSizeExceededException，它实现了 ErrorResponse 接口，自带 413 状态码。所以框架无需任何 advice，兜底响应就是 HTTP 413。

// spring-web → MaxUploadSizeExceededException.java（关键源码）
public class MaxUploadSizeExceededException extends MultipartException
        implements ErrorResponse {

    private final ProblemDetail body = ProblemDetail.forStatusAndDetail(
            HttpStatus.PAYLOAD_TOO_LARGE,            // 状态码 413
            "Maximum upload size exceeded");

    @Override public HttpStatusCode getStatusCode() { return HttpStatus.PAYLOAD_TOO_LARGE; }
    @Override public ProblemDetail getBody() { return this.body; }
}

完整触发链：

DispatcherServlet.doDispatch()
  └─ checkMultipart()                    ← multipart 解析，异常发生点（handler 尚未匹配）
       ├─ request.getParts()  → Tomcat 解析超限
       └─ 抛 MaxUploadSizeExceededException  (implements ErrorResponse, status=413)
             ↓ 此时没有任何业务 advice 能接到（原因见 ③）
Spring Boot 兜底按异常自带状态码响应 → HTTP 413
body: {"status":413, "message":"Maximum upload size exceeded", ...}
结论：你看到的 413 是框架默认行为，语义正确但 body 是英文默认 JSON， 不是本项目统一的 Result。要把它变成友好提示 / 统一结构，才需要下面第 ③ 步的 advice。

③ FileControllerAdvice 统一兜底（已实现）单个 handler

为什么原带 basePackages 不行：容器 multipart 超限在 checkMultipart() 抛 MaxUploadSizeExceededException，此时 handler 尚未确定(null)，带 basePackages 的 advice 对 null 类型判定不适用 （HandlerTypePredicate.test(null) == false），接不到。FileControllerAdvice 因此改为 不带任何 basePackages 的全局 advice。只声明一个 @ExceptionHandler(MaxUploadSizeExceededException.class)，两类超限都汇到这里：

来源异常怎么来的maxUploadSize
容器 multipart 超限（spring.servlet.multipart.max-file-size） Spring 在 checkMultipart() 解析请求时自行抛出（handler 为 null、不知道 pathKey） 容器上限，如 8MB
pathKey 业务超限（attach_<key> 第 2 段 length） FileController.uploadFile 里 file.getSize() > fileConfig.getLength() 时 主动构造并抛出同一个异常：new MaxUploadSizeExceededException(fileConfig.getLength()) 该 pathKey 上限，如 2,000,000 字节 
// FileControllerAdvice（完整实现：全局、无 basePackages）
@RestControllerAdvice
public class FileControllerAdvice extends ControllerReturnAdvice {

    @ExceptionHandler(MaxUploadSizeExceededException.class)
    @ResponseStatus(HttpStatus.PAYLOAD_TOO_LARGE)
    public Result handleMaxUploadSizeExceeded(HttpServletRequest req, MaxUploadSizeExceededException e) {
        log.error("upload file too large, max = {}", e.getMaxUploadSize(), e);
        Result result = Result.fail(new BusinessException(FileError.UPLOAD_OUT_OF_SIZE));
        if (e.getMaxUploadSize() >= 0) {
            result.setData(FileUtility.getInstance().getHumanReadableFileLength(e.getMaxUploadSize()));
        }
        return result;
    }
}
// 刻意不覆写父类 handle(BusinessException)：其它业务异常走 sparrow 原始统一逻辑，不被本文件污染。
// 超限一律抛 MaxUploadSizeExceededException，让上面的 handler 用 e.getMaxUploadSize() 输出限制值。

④ 约定：code=12202 + HTTP 413 + data=可读限制（前端 code 映射）

两类超限最终都返回 FileError.UPLOAD_OUT_OF_SIZE、HTTP 413。前端不解析英文 message，按 code 分支、展示 data：

code = "1"(系统) + 模块22(FileModule.UPLOAD) + "02"(seq) = "12202"
HTTP = 413 PAYLOAD_TOO_LARGE（容器超限与业务超限一致）
data = 可读限制大小（容器上限 / pathKey 上限），如 "8MB" / "1.9MB"
// FileController.uploadFile、file.transferTo 之前 —— 业务超限直接复用 Spring 异常
if (file.getSize() > fileConfig.getLength()) {
    throw new MaxUploadSizeExceededException((long) fileConfig.getLength());
}
// spring-upload.html（error 分支：按 code 识别 + 展示 data）
} else if (result && result.code === "12202") {
    errorEl.textContent = "上传失败：文件大小超过限制"
        + (result.data ? "（最大 " + result.data + "）" : "");
}
边界：pathKey 上限(如 resource≈2MB) < 容器上限(8MB) 时，超限由业务校验抛出（仍是 413）； 若某 pathKey 允许值 ≥ 容器上限，则被容器直接拦截。两条链路 code 相同、data 各自为当前生效上限，前端一套逻辑全覆盖。
